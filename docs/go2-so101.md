# Go2 + SO-101 over SSH

Record a mobile base and a six-motor arm into one LeRobot v3 dataset. The laptop
reads an SO-101 leader and runs the recording UI. The Go2 computer reads the
follower, front RealSense RGB camera and wrist USB camera. SSH transports
commands, telemetry and JPEG frames; final videos use H.264. No ROS is required.

This is an experimental Linux source-checkout example. The recorder runs at
20 Hz; cameras are requested at 30 FPS. There is no claim of hardware camera
synchronization or a trained mobile-manipulation policy.

## Installation

On the laptop, use Python 3.12 and install from the repository root:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e '.[so101,test]'
python scripts/go2_so101_record.py --mock --headless --episodes 1 --episode-seconds 1
pytest tests/test_go2_so101_record.py tests/test_so101_remote.py
```

LeRobot is pinned to the upstream revision used to validate this integration.
Mock mode uses a separate `datasets/go2_so101/mock_*` output and never opens SSH,
USB motors or physical cameras. The scripts are run from the checkout rather
than installed as console commands. Some runtime prompts are currently Russian.

On Go2, the base endpoint needs Python 3.8+, Unitree SDK2 Python and its CycloneDDS
runtime, NumPy, OpenCV, `udevadm`, and the RealSense `rs-enumerate-devices` utility.
OpenCV reads the cameras through V4L2. Configure SDK2 using
the [base adapter guide](guide.md). The arm endpoint uses `python3` and only the
standard library; it talks directly to the Feetech serial bus at 1 Mbit/s.
The SSH user needs camera and serial-device access. Endpoints are sent in memory
at launch; the bridge does not install packages or update firmware on Go2.

## Configuration and calibration

Copy both examples to ignored local files:

```bash
cp configs/go2_dataset_collection.yaml configs/go2_dataset.local.yaml
cp configs/go2_so101_collection.yaml configs/go2_so101.local.yaml
```

In `go2_so101.local.yaml`, set `base_config: configs/go2_dataset.local.yaml`.
Fill these values before connecting:

| Setting | Meaning |
| --- | --- |
| `network.host` | SSH user and Go2 address |
| `network.interface` | DDS interface **on Go2** |
| `network.python`, `network.pythonpath` | Onboard Python with SDK2/camera dependencies |
| `network.camera_device`, `network.wrist_device` | Stable UVC device paths on Go2 |
| `camera.serial`, `camera.usb_serial` | RealSense SDK and UVC serials |
| `arm.leader_port` | Leader USB serial device on laptop |
| `arm.follower_port` | Follower USB serial device on Go2 |
| `arm.leader_id`, `arm.follower_id` | Existing LeRobot calibration IDs |

Calibrate both arms using LeRobot before use. The laptop must have the matching
leader and follower calibration JSON files in its LeRobot calibration cache.
The bridge checks the follower's stored motor calibration against that file.
For boards without unique USB serial numbers, use stable `by-path` names.
Establish and verify the SSH host key interactively first; strict host-key
checking stays enabled. Never put passwords or private keys in YAML.

`GO2_HOST`, `NETWORK_INTERFACE`, `CAMERA_SERIAL`, `LEADER_PORT`, `FOLLOWER_PORT`,
`WRIST_CAMERA`, `TASK`, `DATASET_REPO_ID` and `DATASET_ROOT` override selected
settings. Dataset output is restricted to this checkout's `datasets/go2_so101/`.

## Check and record

```bash
python scripts/go2_so101_record.py --config configs/go2_so101.local.yaml --dry-run
python scripts/go2_so101_record.py --config configs/go2_so101.local.yaml --readonly-check --check-seconds 10
python scripts/go2_so101_record.py --config configs/go2_so101.local.yaml --episodes 1
python scripts/go2_so101_record.py --config configs/go2_so101.local.yaml --resume --episodes 5
```

The read-only check does not enable arm torque or send base motion. Before real
recording, prepare Go2 for walking, align leader/follower poses, and clear the
workspace. The script does not stand up the robot. Starting real recording
enables follower torque. A real session requires the camera window.

Keyboard controls: `i`/`,` forward/back, `j`/`l` turn, Shift + `j`/`l` strafe;
Enter starts the countdown, `n` saves an episode, `r` discards/retries, `q` saves
and exits. Space/`k` holds both platforms, `x` locks and `v` unlocks. Losing window
focus holds the platforms. Ctrl+C or an error discards the unfinished episode.

## Stop and recovery behavior

The base watchdog sends zero velocity after 0.25 seconds without commands. The
arm watchdog latches after 0.5 seconds without arm commands: it refuses new goals
while retaining torque and the last goal. `stop`, normal exit, Ctrl+C and SSH EOF
also retain follower torque. Support the arm before removing power; USB/power or
motor failures cannot guarantee holding. Software watchdogs are not a hardware
emergency stop.

The arm runs in its own loop. A base/camera timeout stops the base and invalidates
the current recording attempt, but the arm can continue following the leader
while its connection and UI heartbeat remain healthy. After stream recovery,
`n` permits base continuation. A failed hardware session requires an explicit
`reconnect` in the terminal, followed by calibration/pose checks; motion does not
automatically resume. Saved episodes remain on disk.

## Recorded schema

| Feature | Values |
| --- | --- |
| `observation.images.front`, `.wrist` | RGB 640 × 480, recorded at 20 Hz |
| `observation.state` | vx, vy, wz, roll, pitch, yaw, six arm positions |
| `action` | vx, vy, wz commands, six arm position goals |

Arm order: shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll,
gripper. Base units are m/s, rad/s and radians; arm joints use degrees and the
gripper uses calibrated 0–100 percent. Actions are acknowledged targets after
limits, not raw leader readings.

Dataset timestamps use the nominal 20 Hz grid. Actual monotonic timestamps,
frame identifiers and command acknowledgments are in ignored `logs/go2-so101-*`
files. Camera freshness and base/arm sample skew are checked, but the cameras
are not exposure-synchronized. The dataset contains neither depth nor audio.

The [Go2 Object Approach collection](go2-object-approach.md) is a separate
Go2-only dataset; it does not contain SO-101 actions or wrist video.
